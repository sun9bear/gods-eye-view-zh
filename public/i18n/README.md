# 多语言界面运行时翻译层

给 God's Eye View 加多语言界面。**对上游源码的改动主要是**：`index.html` 加一行引入，`package.json` 加两个脚本，以及 canvas 绘制路径上的几个可选调用点（`worldOverlay.js` / `frames.js` / `detectionDraw.js`）。

```
public/i18n/
├── gev-i18n.js             引擎：DOM 遍历 + MutationObserver + 语言切换 + t()
├── dicts/
│   ├── index.js            语言注册表（新增语言只改这里）
│   ├── zh-Hans.js          简体中文 ← 唯一真源
│   ├── zh-Hant.js          繁體中文 ← 脚本生成，勿手改
│   ├── ja.js               日本語
│   └── ko.js               한국어
└── README.md               本文件
scripts/i18n-coverage.mjs   覆盖率扫描器（npm run i18n:coverage）
scripts/i18n-visual-audit.mjs 视觉终检（npm run i18n:audit）
scripts/i18n-gen-hant.mjs   繁體生成器（npm run i18n:gen-hant）
scripts/i18n-audit-dicts.mjs 字典审校（npm run i18n:dicts）
scripts/i18n-key-parity.mjs 键位对齐（四语言词条/片段对账）
scripts/i18n-claim-audit.mjs 运行时字符串核对（真实拼接串喂给 t()，五语言判译/漏/半译）
scripts/i18n-runtime-test.mjs 浏览器运行时回归（空白 fixture，页面错误计入判据）
scripts/i18n-live-verify.mjs 生产页面语言入口验收（多分辨率 × 多语言 × 折叠态）
scripts/i18n-restore-diag.mjs 一次性诊断：还原英文的逐项差异
```

当前已接入 5 种可选语言：**English（原文）/ 简体中文 / 繁體中文 / 日本語 / 한국어**。

## 一、为什么用运行时方案

项目本身**没有任何 i18n 机制**——610 个非测试源文件、13.9 万行，全部硬编码英文。
直接改源码有三个硬伤：

| 问题 | 运行时方案的解法 |
|---|---|
| 305 个测试文件里大量断言精确英文串（如 `'USGS HTTP 503'`），改源码会让测试大面积失败 | 源码只加可选钩子（不重写逻辑）；既有测试在本分支下仍通过，但**通过 ≠ 所有行为逐位一致** |
| 上游作者持续更新，改过的几百个文件每次合并都冲突 | 与上游的交集很小：`index.html` 1 行引入、canvas 绘制路径上几个可选调用点、翻牌状态隔离、DISPLAY 面板的可见语言入口、图层芯片的消歧属性（清单见 `README.zh-Hans.md`「本分支改了什么」） |
| 想切回英文对照上游文档/issue 时没有退路 | 内置多语言轮换，随时回到原文 |

代价是 canvas 上绘制的文字要走单独的钩子（见第六节）。

## 二、怎么用

| 操作 | 方式 |
|---|---|
| 默认语言 | 简体中文 |
| 可见语言入口 | DISPLAY（显示）面板下方的原生下拉框；折叠面板时仍保留，支持五种语言 |
| 轮换语言 | `Ctrl+Alt+L` |
| 按 URL 指定 | `?lang=ko`、`?lang=ja`、`?lang=zh-Hant`、`?lang=en`、`?lang=tw` |
| 脚本控制 | `window.GEV_I18N.set('ko')` / `.cycle()` / `.languages` |
| 当前语言 | `window.GEV_I18N.current` |
| 查字典规模 | `window.GEV_I18N.stats()` |
| 记忆 | 选择存在 `localStorage['gev.lang']` |

别名都认：`zh` / `zh-CN` → 简体，`zh-TW` / `zh-HK` / `tw` / `hk` → 繁體，
`jp` → 日本語，`kr` / `ko-KR` → 한국어。
认不出来的值会被忽略（保持当前语言），不会把界面变成空白。

## 三、三个必须规避的坑（已处理，改代码时别删）

**坑一：Material Symbols 图标字体靠「文字连字」渲染。**
图标元素里是字面文本，例如 `<span class="material-symbols-outlined">layers_clear</span>`。
一旦翻译成「清除图层」，图标就会变成一个词——因为连字永远无法形成。
→ 引擎跳过 `class` 含 `material-symbols` / `material-icons` 的整个子树。
→ 这也是为什么字典**大小写敏感**很关键：`Radio`（图层名，要翻）与 `radio`（图标名，不能翻）是两条独立的键。
→ 回归检查：图标元素里的文本应**不含任何中日韩字符**。

**坑二：SVG 内联 `<style>` 的 CSS 文本也是文本节点。**
→ 引擎跳过整个 `svg` 子树。

**坑三：同一个英文串在两处含义不同时，引擎分不出来。**

引擎按**文本串**匹配，没有上下文。实例：路由面板的芯片可视标签是 `CLEAR`（= 清除航线），
机舱天气读数的 `CLEAR` 是「晴」。给全局加 `CLEAR` 键会让芯片变成「晴」；不加则天气永远是英文。

处理办法是让**用处更小的那一侧显式让开**：

| 属性 | 作用 | 用在哪 |
|---|---|---|
| `data-gev-noi18n` | 整棵子树连属性一起跳过 | 不该被碰的元素（图标等） |
| `data-gev-i18n-skip-text` | **只**跳过文本节点，`title` / `aria-label` 照常翻译 | 上述撞车的一侧 |

芯片的 `skipTextI18n` 标记在 `src/layers/directions/index.js` 声明，由 `src/ui/layerPanel.js`
落到属性上。**新增这类撞车时优先考虑加键，只有确实无法区分才用 skip-text**——
被跳过的文本会永远停在英文，属于有意的取舍，不是遗漏。

## 四、字典怎么工作

翻译按 **精确 → 正则规则 → 分段 → 局部** 四步命中，任何一步返回非空就停止：

| 表 | 用途 | 例子 |
|---|---|---|
| `dict` | 整串精确匹配。绝大多数静态标签走这里 | `'Live Flights': 'リアルタイム便'` |
| `rules` | 正则规则，处理动态串 | `CelesTrak · 59s ago` 里的时间后缀 |
| `partial` | 长句里逐片段替换 | HUD 遥测行 `ALT: ` → `高度: ` |

**分段机制**：含 ` · ` 的复合串（`A · B · C`）会被切开逐段查表，任一段命中就拼接输出。
所以 `CelesTrak · never`、`adsb.lol · observed or mapped nearby context` 都不用整串登记。

**命中失败一律回退英文原文**，绝不显示错的译文。上游改了英文文案时，那条会静默变回英文。

### ⚠️ 片段表里放「纯拉丁裸词」会被自动加词边界

片段替换是子串替换，所以裸词键会切进更长的单词里。实测踩到两个：

| 键 | 被误伤的串 | 结果 |
|---|---|---|
| `'EL'` | `GD**EL**T Project` | `GD仰角T Project` |
| `'NORMAL'` | `**NORMAL**IZED` | `正常IZED` |

引擎已系统性处理：**凡是只由拉丁字母组成、不含空格或标点的键，替换时自动加
`(?<![A-Za-z])…(?![A-Za-z])` 词边界**。反向替换同理（防 `km` 命中 `kmh`）。

判定标准是「键里有没有自带的边界字符」，**不是键的长度**——最初只给 ≤3 字符的键加保护，
`NORMALIZED` 照样被切。

边界只排除**字母**、不排除数字，这样 `250KM`、`4X3KM` 里的 `KM` 仍能被正常替换。

**给字典加片段时**：能用带空格的写法（`'ALT '`）就别用裸词（`'ALT'`）；
裸词也能用，引擎会保护，但写清楚意图更省事。

**不要翻译的东西**：品牌与数据源专名（`OpenStreetMap`、`adsb.lol`）、环境变量名
（`GOOGLE_MAPS_API_KEY`）、域名与 URL、城市名、飞机呼号、地理标识（`MGRS: 14R PU …`）、
行业通用缩写（`HUD`、`OSM`、`ION`、`FL280`、`kts`、`NAV`、`GEO`）。

## 五、新增一种语言

**只有三步，不需要动引擎。**

**1. 建字典**——复制 `dicts/zh-Hans.js` 为模板（或从 `dicts/ja.js` 抄，它是最干净的独立语言示例），
改开头三处：

```js
export const LOCALE = {
  tag: 'ko',                                        // BCP 47，会写到 <html lang>
  label: '한국어',                                   // 语言菜单里显示的名字（用该语言自己的写法）
  short: '한',
  aliases: ['ko', 'ko-KR', 'kr'],                   // ?lang= 能用的别名
};
```

然后把三张表逐条换成目标语言。**其余一律不用改。**

**2. 注册**——在 `dicts/index.js` 里加两行：

```js
import * as ko from './ko.js';
export const DICTIONARIES = [zhHans, zhHant, ja, ko];   // 顺序即菜单顺序
```

**3. 扫残留**——`npm run i18n:coverage`，对照输出补齐漏掉的条目。

### 繁體中文是生成的，别手改

`dicts/zh-Hant.js` 由 `npm run i18n:gen-hant` 从简体自动转换生成，文件头有醒目提示。
改完简体重跑一次即可。生成器依赖 `opencc-js`（**不是项目依赖**，只在生成时需要）：

```bash
npm i -D opencc-js        # 装
npm run i18n:gen-hant     # 生成 dicts/zh-Hant.js
npm uninstall opencc-js   # 可以卸掉，生成结果是自包含的
```

转换用 `s2t`（纯字形），**不做台湾/香港用词替换**，避免替使用者做地区词汇选择。
要台湾用词（软体/资讯/网路）就把 `scripts/i18n-gen-hant.mjs` 里的 `to` 改成 `twp`。

### 非 CJK 语言要先压测布局

界面里有若干**固定宽度**容器（如 `#hud-summary` 实测 `clientWidth=420`）。
中日韩用字短，装得下；德语/俄语这类**比英文长 20–40%** 的语言会把面板撑破。
加欧洲语言之前，先按上面三步加字典，再逐屏截图检查有无溢出，必要时收窄译文用词。
阿拉伯语/希伯来语更要命——需要 `dir="rtl"`，整套 HUD 与面板方向都要改，等于另一个量级的工程。

## 六、canvas 补丁

引擎只能处理 DOM。canvas 上的文字走另一条路：翻译层把纯函数 `t()` 挂在
`window.GEV_I18N` 上，`src/` 侧按 `globalThis.GEV_I18N?.t?.(s) ?? s` 调用。
翻译层未加载（含单元测试的 Node 环境）时原样返回，行为与改动前完全一致。

### 实测结论：canvas 上的文字绝大部分是数据

用挂钩 `CanvasRenderingContext2D.prototype.fillText` 的方式把真实绘制出来的字符串
全部捕获下来，结果是：**79 条唯一字符串里全是呼号（`ANX1210`、`RCH748`）、飞行等级
（`FL310`）、ICAO 地址（`ae68a6`）、机尾号（`83-23907`）、火箭名（`FALCON 9 BLOCK 5`）、
摄像头专名**——即全部是数据。真正需要翻的只有 `NO FEED`、`IMAGE`、`STALE`、`OSM MAPPED`
这一小撮界面词汇。

所以 canvas 补丁的价值**主要在打通链路 + 修正宽度测量**，而不是翻译大量文案。

### 改动的三个位置

| 文件 | 改了什么 | 为什么 |
|---|---|---|
| `src/overlays/worldOverlay.js` | `normalizeEntry` 里 title / details 过 `overlayText()` | **必须早于测量**，见下 |
| `src/layers/cctv/frames.js` | 状态行整串过 `t()` | `IMAGE` / `NO FEED` 这类状态代码可翻 |
| `src/data/detectionDraw.js` | `monoTextWidth` 改用 `textAdvance` 计格数 | 中日韩全角占两格，见下 |

### 关键点一：翻译必须发生在测量之前

世界覆盖层卡片的宽高由 `measureOverlayEntry` → `ctx.measureText` **实测**得出
（`worldOverlayDraw.js:80`）。所以翻译必须放在 `normalizeEntry`（`worldOverlay.js:420`）
——先翻再测，译文卡片尺寸自动正确。若在 `fillText` 前才翻，背景框会按英文宽度算，
译文直接溢出卡片。

### 关键点二：等宽字体下全角占两格

检测叠加层不调 `measureText`，而是用 `monoTextWidth(text, charWidth)` 做
「字数 × 字宽」的固定步进估算（热路径优化）。中日韩全角 glyph 占两个等宽格，
直接用 `text.length` 会算少一半，标签背景会被裁掉。
`textAdvance()` 按单元格计：ASCII 记 1，东亚全角记 2。纯 ASCII 结果与改动前完全一致（有测试钉住）。

## 七、语言之间互切是怎么做到的

两个 WeakMap 就够：

- **原文快照 `ORIGINAL`**：每个节点第一次被翻译前，先把**英文原文**存下来。
  之后无论切到哪种语言，都从这份英文重新翻译，所以语言之间可以任意跳转
  （简体 → 繁體 → 日本語 → 英文 → 简体…），也可以随时回到原文。
- **已写值追踪 `APPLIED`**：应用会持续重写 HUD 这类高频文本。若节点当前值
  ≠ 我们上次写的值，说明是应用改写的 → 用当前值刷新原文快照。
  没有这一步，切语言时会还原出过期的旧文案。

### 踩过的坑：新建节点带着上一门语言的残留

应用偶尔会**新建**一个节点，并把它读到的、已被我们翻译过的文本写进去（不是重新构造英文）。
这种节点没有快照，若直接拿当前值当原文，就会把上一门语言的残留带到下一门语言。
**实测症状：日文界面里 HUD 摘要行出现简体的「正常」。**

→ 解法是 `seedOriginal()`：为没有快照的节点建立原文时，若当前值含中日韩字符，
先用跨语言反向表还原成英文。反向表收**所有**语言的译文，因为污染发生时激活的是哪种语言并不确定。

**同一个坑在属性上也会发生，而且更隐蔽。** 应用会把**已翻译的**面板标题拼进 tooltip
（`'Expand ' + 标题`），于是 title 变成 `"Expand 定位"`。
症状是**英文模式下漏出中文**：`Expand 定位` / `Expand 数据图层`。
→ `handleAttrs` 建立属性原文快照时，**必须同样过 `seedOriginal()`**。
（最初只在文本节点路径加了，属性路径漏了，结果英文模式里残留了 16 条中文 tooltip。）

### 第三个坑：组合式 tooltip 要加规则

即便原文快照正确，`"Expand 定位"` 这种串在非英文语言下也**整串字典键命中不了**——
字典里只有 `"Expand LOCATION"` 这种纯英文形式。
→ 每份字典都要加两条规则兜住组合形式：

```js
[/^Expand (.+)$/, (m) => `展开 ${m[1]}`],
[/^Collapse (.+)$/, (m) => `收起 ${m[1]}`],
```

纯英文形式由精确表先命中，不受规则影响。

### 第四个坑：复合行里的词要同时登记到片段表

`#hud-summary` 是**单个文本节点**，内容是
`"NORMAL STREET NEAR <地名> 0KM | NORTH AMERICA | ALT 627M | …"`。
它的首词 `NORMAL` 只在**精确表**里，而精确表要求整串命中——所以复合行里的它翻不到。
→ 这类词必须在**片段表**里也登记一份。观测带与大区词表来自 `src/hud.js` 的
`_viewBand()` / `_regionLabel()`：`STREET` `CITY` `METRO` `REGIONAL` `GLOBAL`、
`ARCTIC` `ANTARCTIC` `NORTH AMERICA` … `NORTHERN OCEANIC GRID`。
→ **顺序要紧**：`ANTARCTIC` 必须排在 `ARCTIC` 前面，否则会被切成 `ANT北极`。

## 页面语言入口回归（生产构建）

构建后运行 `node scripts/i18n-live-verify.mjs`，自动在 loopback 地址提供 `dist/`；需要本机 Edge/Chrome。输出 `outputs/i18n-component-audit/live-report.json` 与 `panel-*.png`。

- 范围：1366×768、1600×900、1920×1080；五语言；DISPLAY 面板折叠/展开，共 30 个语言入口场景。另测英文固定标签还原、日语无语言参数重新导航后的持久化、快捷键同步与焦点。
- 失败会返回非零退出码，页面异常和截图失败也计为失败。外部网络请求被阻断，因此不代表在线底图、服务端接口或数据源恢复。
- 启动完成依据源码真实退场方式：加载屏 `.hidden` 且 `visibility:hidden`，不是 `display:none`（该值仍为 `flex`）。
- 默认语言为简体，英文基线必须显式使用 `?lang=en`；测试持久化时不带语言参数。还原只比较固定控件，不能比较包含时钟与实时计数的整页文本。
- 可见性采样应位于原生 select 内部，不能把圆角透明区误判为遮挡；必须同时检查控件边界与祖先裁切。
- 这是语言入口验收，不是全站漏译穷举、所有面板布局验收或母语审校。

## 八、覆盖率

`npm run i18n:coverage`（需先 `npm run dev`）会展开所有面板并列出仍是英文的文本与属性。

早期单次 DOM 扫描曾记录简体 85 条、日语/韩语各 93 条残留；这些是历史场景快照，不是当前全站覆盖率。字典已继续更新，规模应以 `window.GEV_I18N.stats()` 为准。

**撤回“残留全部为刻意保留”的全站结论。** 已核对的品牌、机构名和技术缩写可以保留；没有触发的镜像状态、重试模板和动态面板仍须单独验证，不能由某一次扫描推断。

### 另一条互补路径：直接问引擎（`npm run i18n:strings`）

DOM 扫描只能证明「当时那一屏」，而且抓取瞬间可能读到「上游刚写回原文、翻译层还没处理」的
混合态（见后文「时序伪影」）。`scripts/i18n-claim-audit.mjs` 换一条路：把**真实运行时代码
拼接出来的字符串**直接喂给 `window.GEV_I18N.t()`，由引擎自己回答，完全不受时序影响。

它把每条判成三态：

| 判定 | 含义 |
|---|---|
| 译 | `t()` 返回与原文不同，且原文里的英文词已消失 |
| 半译 | 返回了译文，但原文的英文词还残留一部分（如 `RETRO · 密集 · 6.0s`） |
| 漏 | `t()` 原样返回，说明四步匹配全部未命中 |

覆盖会话费用、模型提示、场景镜头 meta、Overpass 重试组合串、天气/云量、成对文案
（Enable/Disable、Pause/Resume/Play）、图层状态 aria-label。**新增动态串时应同步加用例**，
否则这条路径也保护不到它。

> 三个需要浏览器的脚本（`i18n:strings`、`i18n:live`、`i18n-runtime-test.mjs`）**故意不接入 CI**：
> 它们依赖本机 Edge/Chrome，而 CI runner 用 `PUPPETEER_SKIP_DOWNLOAD=1`。CI 里只跑不需要
> 浏览器的 `npm run i18n:parity`。**单测通过不能代替翻译层的集成检查**，改字典/规则后请在
> 本机把这三个脚本跑一遍。

### 覆盖率的两个盲区（必须另跑 `npm run i18n:audit`）

覆盖率的判定是「含拉丁字母且**不含**中日韩」，所以它报不出这三类：

1. **中英混杂串** —— 如 `Expand 定位`（应用把已翻译的标题拼进 tooltip）
2. **英文模式下的译文残留** —— 属性路径漏了反向还原时会出现
3. **状态依赖的串** —— 只在特定状态出现，扫描那一刻没触发就漏了。
   实测踩到的三个：`just now`（`src/ui/layerPanel.js` 的 `_timeAgo()`）、
   `LOADING` / `DEGRADED`（同文件 `FEED_STATE_LABELS`）、
   以及 `250nm regional fallback`（`server/providers/aircraft/opensky.js` 的
   `X-Flight-Coverage` 响应头值——只有航班回落到 adsb.lol 时才出现）。

**结论：`i18n:coverage` 干净不等于覆盖完了。** 加语言或改文案后，三项一起跑：
`i18n:coverage`（找漏译）+ `i18n:audit`（找混杂/裁切/英文残留）+ 人眼看截图。

历史快照中已核对且有意保留的例子包括：品牌 `GOD'S EYE` / `VIEW` 在
日韩界面里保持拉丁字母（惯例），军事编号 `KH11-…`，技术缩写 `GSD` / `NIIRS` / `ONA` / `FPS`，
以及机构名 `Transport for NSW`。

刻意保留的类别：URL 与域名、许可证标识、许可方要求逐字呈现的署名句
（`© OpenStreetMap contributors`、`Powered by TfL Open Data`）、品牌与机构名、
环境变量名、行业通用缩写、地理与军事标识。

**署名灯箱的翻译规则**：只翻译描述性文字，许可证标识、机构与品牌名、URL、文献引用，
以及被许可方要求逐字呈现的署名句一律保留英文原文。这样读者能读懂数据来源与授权，
同时不削弱署名本身的法律可识别性。

### 字典审校（`npm run i18n:dicts`）

覆盖率扫描只能告诉你**哪些没翻**。它说不出「翻错了」。字典审校器补这一块——它只报
**机器能客观判定**的问题，不评价译文好坏（那是人的事）。

```bash
npm run i18n:dicts           # 写 i18n-dicts-report.json（已 gitignore）
npm run i18n:dicts -- --print
```

五类检查：

| 检查 | 抓什么 | 为什么可靠 |
|---|---|---|
| **与中文雷同** | 日/韩译文与 `zh-Hans` **逐字相同** | 日文和韩文不可能恰好与中文用同一串汉字。撞上就是从中文复制过来忘了改。这是最有效的漏译检测，**不需要任何字符表** |
| **异文字混入** | 日文字典里出现简体专有字；韩文字典里出现汉字/假名 | 「級」vs「级」只差一笔，肉眼必漏。字符表只收「中日字形不同」的字，同形字一律不进表，否则满屏误报 |
| **术语撞车** | 多个英文键译成同一个词 | 读者会分不清两个不同的 UI 概念 |
| **文体分布** | 日：です・ます vs だ、韩：합니다 vs 해요 vs 한다 | 整句混用不同敬体是典型机器翻译痕迹 |
| **标点一致性** | 全角/半角冒号、分号、括号混用 | 同一份字典里两种写法并存必然是疏漏 |

#### 读结果时必须知道的两件事

1. **同形汉字词不是问题。** 中日共用大量汉字词（北 / 高度 / 密度 / 船舶 / 水平 /
   降水 / 音量 / 公共交通），它们出现在「与中文雷同」清单里是**正常**的。真正要处理的
   是那些**日文里根本不这么说**的词——例如曾经的「非商用」（日文标准译法是**非営利**，
   CC 官方日文版用语）。
2. **有些撞车是有意保留的**，不要「修」：

   | 撞车 | 为什么保留 |
   |---|---|
   | `SAT` / `Satellites` → 卫星 | 分别在地图源选择器和图层列表，位置不同，上游英文本就同义 |
   | `CAMERAS` / `CCTV` / `Cameras` → カメラ | 同上。图层与面板不在同一处出现，三语一致 |
   | `CONTACT` / `CONTACTS` → 対象 | 单复数同译 |
   | `Sharpen` / `Sharpening` → シャープ | 参数名与分区标题，上游同义 |
   | `Previous filtered station` / `Previous filtered radio station` | 同一 aria-label 的两个上游变体 |
   | `MAPPED INSTALLATION` / `Mapped Installations` | canvas 标签与图层名，同一概念 |

#### 同一轮复审推翻的另外三个结论

| 原来的说法 | 实际情况 |
|---|---|
| 「残留英文全部为刻意保留」 | **范围过大**。`i18n:coverage` 扫的是**渲染后的 DOM**，只能看到扫描那一刻的状态——初始为 OFF 的控件就只收录了 OFF 版本。实测 `CCTV ON` / `COVERAGE OFF` / `AUTO HOP ON` / `PROJECTION OFF` / `ENABLING` / `DISABLING` / `PAUSE` / `RESUME` / `1 KEY WAITING` 全部漏收 |
| 「只改 DOM，不改业务逻辑」 | **不成立**。`src/splitFlap.js:456` 用 `element.textContent === next` 判断幂等，`:424` 用 `element.textContent !== expected` 判断收尾——**翻译改了 DOM 文本就会破坏这两处判断**。调用点 `src/ui/cctvPresentation.js:229` |
| 「切回英文仍有问题就是上游问题」 | **不成立**。切英文不会撤销 canvas 宽度计算、翻译观察器，也不会撤销本分支对 User-Agent 和测试断言的改动。要归属上游必须在**未修改的上游基线**上复现 |

**教训（已写入审校流程）**：

1. 审校译文**必须查实际使用上下文**，不能靠词表邻接或字面推断
2. 用 DOM 扫描做覆盖率，**只覆盖「当前状态」**；要覆盖全部状态必须从源码穷举字符串
3. 声称「不影响行为」之前，要确认被改的 DOM 文本**没有被业务逻辑当作状态读取**

#### 标点规范的结论：三语都已正确，但规范不同

| 语言 | 规范 | 实测 |
|---|---|---|
| 简体 / 繁體 | 全角冒号、全角括号 | 一致 |
| 日本語 | **全角**冒号「：」、全角括号「（）」、读点「、」 | 46:0 ✅ |
| 한국어 | **半角**冒号「: 」、半角括号「()」、半角逗号 | 25:0 ✅ |

**韩文用半角标点是正确的**，不要为了「统一」把它改成全角。

### ⚠️ 读 `i18n:audit` 报告时的一个陷阱：时序伪影

`i18n:audit` 是加载页面、sleep 一段、再读 DOM。但 `#hud-summary` 这类元素
**每秒被应用重写一次**——抓到「应用刚写回英文、翻译层还没处理」的那一瞬间，
报告里就会留下半英半译的串。

**实测症状**：报告里 HUD 摘要显示 `... 0KM | 北米 | 高度 627M ...`，看起来像 `KM`
规则失效。但直接问引擎就正常：

```js
window.GEV_I18N.t('0KM |')   // → '0km |'   ✅
```

**判断方法**：同一个元素在不同场景（welcome / panels / keys / scenes）的报告里值不一致，
就是时序问题，不是字典问题。**要确认字典行为，永远直接调 `t()` 下结论，不要拿审计文本当证据。**

## 九、已知问题

**HUD 摘要行截断。** `#hud-summary` 是 `white-space: nowrap; overflow: hidden; text-overflow: ellipsis`
的固定宽度容器（实测 `clientWidth=420`）。实测同一元素：英文 `scrollWidth=920`（比例 2.19），
简体中文 `823`（比例 1.96）——**中文比英文还窄 11%，截断是项目原生行为，不是翻译引入的**。

**偶发的单位大小写不一致。** HUD 摘要行是高频重写节点，极少数渲染瞬间片段替换未命中，
会显示英文原文（如 `0KM` 而非 `0km`）。符合「未命中回退英文」的设计，下次重写即自愈，不影响阅读。

**`ONA`（离天底角）在日/韩保留缩写。** 简体/繁體译作「偏角: 」，日本语与韩国语沿用 HUD 的
缩写惯例保持 `ONA: `（与其它航空缩写一致）。**这个术语选择需要母语者定夺**，此处只保证四种
语言的键位对齐、不留结构缺口。

**` · ` 分段是宽松的，会产出「半中半英」。** `bySegments` 只要求「至少一段被译」，品牌名
（`CelesTrak`、`Overpass`）必须原样留下，所以不能要求「全部段都译」。代价是当某段恰好
没有词条时，会拼出 `RETRO · 密集 · 6.0s` 这种混排。**处理办法是给缺的那一段补词条或补规则**，
不要收紧分段策略。可用性影响：这类混排只出现在动态串上，静态标签不受影响。

## 十、维护提示

- 上游改了英文文案 → 字典键失配 → 那条静默变回英文。**不会报错**，这是刻意设计。
- 定期跑 `npm run i18n:coverage` 可量化覆盖率与发现失配。
- **改完字典跑 `node scripts/i18n-key-parity.mjs`**：某个键只补了一种语言时，其余语言会静默
  显示英文，覆盖率扫描与单测都不会有反应——只有键位对账能发现。
- **改完规则跑 `node scripts/i18n-claim-audit.mjs`**：它把真实拼接串直接喂给 `t()`，
  判定「译 / 漏 / 半译」，不受 DOM 抓取时序影响（第八节「时序伪影」的规避办法）。
- **动态串优先写规则，不要冻结成整串词条**。冻结词条只在「默认态那一串恰好完全一致」时命中，
  参数一变就静默回落英文；会话费用、模型提示、场景镜头、Overpass 重试组合串都踩过这个坑。
- 不要为了「翻得更全」把品牌名和变量名也翻掉——发布合规上，署名与许可证名称必须保持可识别。

### 明确不改的（下轮别再当 bug 修）

- **品牌 / 专有名词**：`GOD'S EYE`、`VIEW`、`OpenSky Network`、`OpenStreetMap`、`USACE`、
  `GTFS-RT` 在 ja/ko 故意缺键。
- **同义撞车**：`SAT`/`Satellites`、`CONTACT`/`CONTACTS`、`Sharpen`/`Sharpening`——不同面板
  的单复数与参数名，保留。
- **中日同形词**（北/高度/密度/船舶/水平…）在「与中文雷同」清单里出现是正常的。
- **`CLEAR` 芯片的可视标签**：见第三节坑三，用 `data-gev-i18n-skip-text` 有意让开。

### 回归检查清单

改动本目录后在浏览器里确认：

1. **图标没被破坏**：`document.querySelectorAll('.material-symbols-outlined')` 里每个元素的文本
   仍应是 `radio`、`public`、`layers_clear` 这类连字名，**不含任何中日韩字符**。
2. **语言能往返回去**：`set('ja')` → `set('en')` → `set('zh-Hans')` 应逐字还原，
   尤其检查 `#hud-summary` 这类高频重写的元素有没有残留上一门语言的字符。
3. **无报错**：控制台 `console.error` 计数应为 0。
4. **功能未受影响**：最容易踩雷的是「显示文字看起来像查询键」的控件。已确认安全的一例是
   城市预设按钮——它用 `dataset.locationId` 定位，`textContent` 只用于显示，
   所以翻译标签不会让点击失效。
5. **无中英混杂、且英文模式无译文残留**。`npm run i18n:coverage` 报不出来这两类
   （它只找「拉丁字母且无中日韩」的串），要在浏览器里另查：

   ```js
   // 找残留的混杂 tooltip —— 每种非英文语言都应为 0 条
   [...document.querySelectorAll('[title],[aria-label]')]
     .flatMap((e) => ['title', 'aria-label'].map((a) => e.getAttribute(a) || ''))
     .filter((v) => /^(Expand|Collapse)\s/.test(v.trim()) && /[\u3040-\u30ff\u4e00-\u9fff\uac00-\ud7a3]/.test(v));
   // 切到 en 后再跑一次，应为 0 条（若出现中文，说明属性路径漏了 seedOriginal）
   ```

6. **跑字典审校**：`npm run i18n:dicts`。改过任何字典文案后都该跑一次——它能抓到
   覆盖率扫描看不见的「与中文雷同」和「异文字混入」。**读结果时先看第八节的两类误报
   说明**（中日同形汉字词、以及有意保留的同义撞车），否则会把正常情况当 bug 修。
